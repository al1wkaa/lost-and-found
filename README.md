# «Нашлось!» — сайт потерянных и найденных вещей

Flask-приложение: пользователи публикуют объявления «потерял» и «нашёл»,
а система сама подбирает вероятные совпадения пар «потерял — нашёл» и
предлагает автору подтвердить их и связаться со вторым участником.

Весь серверный код — на Python (Flask + Jinja2 + SQLite), без JavaScript:
формы отправляются обычными POST-запросами, страницы отдаются Jinja2
с автоматическим экранированием.

## Возможности

- Регистрация и вход (Flask-Login), пароли хранятся в виде хэшей.
- Подача объявления: тип (потерял/нашёл), категория, место, дата,
  заголовок, описание, фотография (Pillow, до 5 МБ, безопасное имя).
- Поиск и фильтры по списку объявлений: текстовый запрос (работает
  с русской раскладкой ввода, включая Ё/е), категория, место, дата.
- Пагинация: по 9 карточек на странице.
- Автоматический подбор совпадений сразу после публикации находки
  и «потери»: оценка 0–100, показываются пары не ниже 60 баллов.
- Обработка совпадений: «Это моё» (подтвердить — открываются контакты
  обоих участников) или «Не подходит» (скрыть совпадение).
- Личный кабинет: свои активные и закрытые объявления, статистика,
  предложенные совпадения.
- Профиль: редактирование имени и контактов, смена пароля.
- Контакты автора объявления видны только вошедшим пользователям.
- Обработка ошибок: собственные страницы 403, 404, 413 и 500.

## Установка и запуск на Windows

```powershell
# 1. Клонировать репозиторий и перейти в папку проекта
cd lost-and-found

# 2. Виртуальное окружение (один раз)
python -m venv venv

# 3. Активация (PowerShell)
venv\Scripts\Activate.ps1
# или в cmd: venv\Scripts\activate.bat

# 4. Зависимости
pip install -r requirements.txt
# для разработки и тестов дополнительно:
pip install -r requirements-dev.txt

# 5. Запуск
python app.py
```

Сайт откроется на http://127.0.0.1:5000. База `lostfound.db` создаётся
и наполняется справочниками (категории, места, соседи мест) автоматически
при первом запуске (`db.py`).

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATABASE_PATH` | `lostfound.db` в корне проекта | путь к файлу базы SQLite |

| `SECRET_KEY` | нет | ключ подписи сессий и CSRF; в production обязателен |
| `FLASK_ENV` | — | при значении `production` без `SECRET_KEY` приложение отказывается запускаться |

Пример для production:

```powershell
$env:FLASK_ENV = "production"
$env:SECRET_KEY = "длинная-случайная-строка"
```

## Алгоритм совпадений

Сразу после публикации объявления система сравнивает его со всеми
активными объявлениями противоположного типа. Пара отбрасывается без
подсчёта, если **категории разные** или **находка датирована раньше
даты потери** (нельзя найти вещь до того, как её потеряли).

Оценка пары (0–100) складывается из пяти составляющих:

| Составляющая | Вес | Как считается |
|---|---|---|
| Категория | 30 | совпадение категории — обязательное условие, иначе пара отбрасывается |
| Место | 25 | то же место — 25, соседнее (таблица `place_neighbors`) — 10 |
| Время | 20 | разница дат: ≤1 день — 20, ≤3 — 15, ≤7 — 10, ≤14 — 5 |
| Текст | 15 | доля общих «основ» слов (первые 5 букв, без стоп-слов) заголовка и описания |
| Фотография | 10 | заготовка: балл, если фото есть у обоих объявлений |

Пары с оценкой **не ниже 60** (`MIN_SCORE`) сохраняются в таблицу
`matches` со статусом `new` и показываются автору потерянного
объявления (и в личном кабинете). Автор может:

- **подтвердить** («Это моё») — статус `confirmed`, оба участника видят
  контакты друг друга;
- **отклонить** («Не подходит») — статус `rejected`, совпадение скрывается.

Подробности подбора весов и пограничные случаи — `docs/matching-tuning.md`.

## Безопасность

- Все SQL-запросы параметризованы (`?`), поля сортировки собираются
  из белого списка фрагментов; строки LIKE экранируются.
- Jinja2 автоматически экранирует вывод, модификатор `|safe` не используется;
  любые пользовательские данные (текст, id, имена файлов, ссылки `next`)
  не приводят к 500-й ошибке и не ломают разметку.
- CSRF-защита всех POST-форм через Flask-WTF; устаревшая/чужая сессия
  получает страницу с сообщением «Сессия устарела, повторите действие».
- Пароли — хэши Werkzeug; минимум 8 символов при регистрации.
- Фотографии: проверка содержимого через Pillow (не просто расширение),
  лимит 5 МБ (страница 413), имя файла — uuid, расширение определяется
  по фактическому формату; файлы отдаются из `uploads/` без исполнения.
- Cookie сессии: `HttpOnly`, `SameSite=Lax`, `Secure` в production.
- Секретный ключ — только из переменной окружения; в production без него
  приложение отказывается запускаться.
- Открытые перенаправления исключены: параметр `next` принимает только
  внутренние адреса.
- Контакты автора видны только вошедшим; закрыть совпадение или объявление
  может только его автор (403 для остальных).

## Тесты

```powershell
pip install -r requirements-dev.txt
.\venv\Scripts\python.exe -m pytest tests -q
```

74 теста: чистая функция `score_pair`, поиск и фильтры, пагинация,
валидация форм и загрузка фото, права доступа, обработка совпадений,
CSRF. Тесты работают на временной базе (переменная `DATABASE_PATH`
переназначается в `tests/conftest.py`), боевая база не затрагивается.

Быстрые проверки:

```powershell
.\venv\Scripts\python.exe -m pyflakes app.py db.py matching.py seed_demo.py tune_matching.py
```

## Ограничения

- SQLite — одна запись за раз; для многопользовательской боевой нагрузки
  понадобится PostgreSQL и миграция схемы.
- Фотографии хранятся на диске локально; при нескольких инстансах
  нужен общий диск или объектное хранилище.
- Совпадения не учитывают пересечение фотографий по содержимому
  (вес W_PHOTO — заготовка под будущее сравнение изображений).
- Поиск по тексту — простой по «основам» слов, без морфологии и опечаток.
- Уведомления нет: о новых совпадениях пользователь узнаёт в кабинете.

## План развития

1. Сравнение фотографий по содержимому (включить W_PHOTO по-настоящему).
2. Почтовые уведомления о новых совпадениях.
3. Поиск с учётом морфологии и опечаток.
4. Комментарии/чат в рамках пары «потерял — нашёл».
5. Модерация объявлений и жалобы.
6. Мобильное приложение или PWA.
