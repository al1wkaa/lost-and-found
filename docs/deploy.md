# Публикация «Нашлось!» на Render

## Что важно понимать заранее

На бесплатном тарифе Render:
- **диск не постоянный** — при перезапуске сервиса файлы на диске очищаются,
  поэтому база SQLite и загруженные фотографии **пропадут**;
- сервис **«засыпает»** после 15 минут простоя, первый запрос после сна
  обрабатывается медленно (до минуты);
- переменные `DATABASE_PATH` и `UPLOAD_DIR` указывают на локальные пути внутри
  проекта — это нормально для демо, но данные живут только до перезапуска.

## Шаги публикации

1. **Выложите репозиторий на GitHub** (ветку `backend-features` слейте в
   основную или выберите её при создании сервиса).

2. На сайте [render.com](https://render.com) войдите в аккаунт и нажмите
   **New → Web Service**.

3. **Подключите репозиторий**: выберите GitHub, найдите репозиторий
   `lost-and-found` и нажмите *Connect*.

4. Заполните настройки сервиса:
   - **Name**: `lost-and-found` (по нему сформируется адрес);
   - **Runtime**: Python 3;
   - **Build Command**: `pip install -r requirements.txt`;
   - **Start Command**: `gunicorn app:app`;
   - **Instance Type**: Free.

5. В разделе **Environment** добавьте переменные окружения
   (можно также взять из `render.yaml`):
   - `SECRET_KEY` — нажмите *Generate*, чтобы Render создал случайное значение;
   - `PYTHON_VERSION` — `3.12.3`;
   - `DATABASE_PATH` — `/opt/render/project/src/lostfound.db`;
   - `UPLOAD_DIR` — `/opt/render/project/src/uploads`.

6. Нажмите **Create Web Service** и дождитесь сборки (2–5 минут).
   В логах должно быть видно, что `gunicorn` поднял приложение, а таблицы
   и справочники создались при первом импорте (`init_db()` вызывается при
   импорте `app.py`).

7. **Проверка**: откройте адрес вида `https://lost-and-found.onrender.com/`,
   пройдите сценарий: регистрация → вход → публикация объявления → лента.

## Что осталось сделать вручную

- Создать сервис в аккаунте Render (нужен доступ к аккаунту).
- Проверить сайт по реальному адресу после деплоя.
- При желании — свой домен и платный тариф с постоянным диском
  (или переход на PostgreSQL, см. ограничения в README.md).
